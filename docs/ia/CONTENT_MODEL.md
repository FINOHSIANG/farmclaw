# 四时内容模型

## Core entities

| Entity | User meaning | Key identifiers | Primary surfaces | Permissions notes |
| --- | --- | --- | --- | --- |
| 农场 | 一个经营或展示范围 | `farm_id` | 今日、农场、系统 | 用户只能看到授权农场 |
| 地块/温室 | 可定位、可监测、可作业的空间对象 | `field_id`、几何边界 | 农场、对象详情、地图 | 地理范围和编辑权限分离 |
| 作物批次 | 一批有生命周期和台账的作物 | `crop_batch_id` | 生产、作业、台账 | 关闭后只读，允许补录并审计 |
| 设备/数据源 | 传感器、摄像头、网关、气象源 | `device_id`、`source_id` | 农场、数据健康、系统 | 运维可改，生产人员只读 |
| 遥测/图像 | 观测事实和原始证据 | `measurement_id`、`captured_at` | 趋势、Agent 依据、台账 | 不可静默覆盖，修订需留版本 |
| 预警/事件 | 需要判断或处置的问题 | `alert_id`、`incident_id` | 今日、预警中心、作业 | 支持确认、分派、升级、关闭 |
| Agent 会话 | 与四时的连续上下文 | `conversation_id` | 智能 | 按农场和成员隔离 |
| 建议/计划 | Agent 生成的可审查方案 | `proposal_id`、`policy_revision` | 智能、今日 | 中高风险需具名审批 |
| 任务/工单 | 人或设备要完成的工作 | `task_id` | 作业、今日、对象详情 | 负责人和状态变更可审计 |
| 执行结果 | 任务实际回执和现场证据 | `execution_id` | 任务详情、台账、智能 | 区分已提交、已接收、执行中、已完成、失败 |
| 投入品 | 种子、肥料、生物农药等 | `input_id`、批号 | 台账、批次详情 | 白名单、库存和使用权限 |
| 采收批次 | 对外销售和追溯的结果对象 | `harvest_batch_id` | 台账、报告、二维码 | 质量与认证材料需锁定版本 |

## Relationships

- 一个农场包含多个地块，一个地块可在不同时间承载多个作物批次。
- 一个作物批次拥有多个农事计划、投入品使用、监测记录、预警和采收记录。
- 一个设备或数据源可以服务多个地块，但每条观测必须记录当时的绑定关系。
- 一个 Agent 建议只引用当时可见的证据快照，并可生成一个或多个任务。
- 一个任务可以包含多个执行步骤和现场证据，关闭前必须有复核结果。
- 一个采收批次聚合一个作物批次的关键台账事件，并生成追溯报告。

| Entity | List/collection | Detail | Create/edit | Related content |
| --- | --- | --- | --- | --- |
| 地块/温室 | 地块列表 | 地块详情 | 新建、导入边界、绑定设备 | 批次、趋势、任务、预警 |
| 作物批次 | 批次列表 | 批次时间线 | 建档、变更阶段、关闭 | 投入品、采收、认证 |
| 预警/事件 | 事件队列 | 事件处置页 | 规则生成、人工上报 | 证据、任务、升级记录 |
| Agent 建议 | 建议队列 | 建议审查页 | 由会话或规则生成 | 依据、审批、任务、回执 |
| 任务/工单 | 任务列表/日历 | 任务详情 | 创建、派单、转派 | 现场证据、结果、台账 |
| 采收批次 | 采收列表 | 追溯报告 | 采收登记、材料上传 | 批次、质量、二维码 |
