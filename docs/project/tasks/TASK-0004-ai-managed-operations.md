# TASK-0004 AI 托管运营

创建日期：2026-08-25
状态：已完成

## 目标

- 增加可解释、可审批、可停止、可审计的 AI 托管功能。
- 支持观察、辅助、自动三种模式，根据遥测、节点和安防状态形成托管任务。
- 高风险动作必须人工批准；演示环境不把网关提交伪装为设备已经执行。

## 非目标

- 不在前端保存模型密钥、设备凭据或生产控制权限。
- 不绕过现有网关直接控制真实设备。
- 不在本阶段训练模型、接入外部 LLM 或建设生产规则平台。

## 范围

- 可解释本地规则引擎：灌溉、温度、湿度、光照、pH、节点健康、摄像头和围栏告警。
- 托管状态机：建议、待审批、已批准、已提交、拒绝、暂停、阻断。
- 模式切换、人工审批、提交、拒绝、紧急停止、重新评估、审计记录与护栏。
- 低风险自动模式仅提交到现有网关或执行安全的前端状态动作；高风险始终人工确认。

## 验收标准

- 不同输入能稳定生成对应风险和证据的任务。
- 观察/辅助/自动模式状态转换正确。
- 高风险任务不会自动执行。
- 托管动作进入事件流和审计记录，并明确“已提交/模拟”语义。
- 桌面和移动端可用，构建及现有测试不回归。

## 回滚方案

- 删除 AI engine/composable/panel 和 HUD 入口即可恢复现有地图与安防功能。

## 风险与护栏

- 高风险、安防、有机投入品和不可逆动作必须人工确认。
- 离线节点、数据过期或置信度不足时阻断自动提交。
- 紧急停止必须立即暂停队列，但不虚构已撤销真实设备动作。
