# TASK-0009 AI 模型与知识库切换管理

创建日期：2026-08-25
状态：已完成

## 目标

- 在 AI 托管中心增加模型与知识库配置入口。
- 展示当前执行引擎、知识来源和配置版本，为新任务记录生成来源。
- 在无真实 Provider、向量库和 RAG 后端时提供诚实降级，不把前端示例配置描述为真实连接。

## 范围

- AI 托管详情增加“配置”页签，内部区分“模型 / 知识库”。
- 模型单选、知识库多选的状态模型、阻断反馈、审计与事件流。
- 当前规则基线与内置有机农业规则包保持本地就绪；未来 Provider/向量知识库仅显示未配置。
- 新生成任务记录 engineId、knowledgeBaseIds 和 configRevision。
- 桌面与 390×900 移动端交互、自动化校验、构建、回归与独立复核。

## 非目标

- 不在浏览器接收、保存或测试 API Key、Provider 端点和知识原文。
- 不伪造模型健康、推理延迟、Token、文档数、切片数和向量索引状态。
- 不在现有 WebSocket Gateway 内临时实现生产级密钥、模型路由、文档接入或向量检索。
- 不允许配置切换绕过 Dry Run、人工审批、紧急停止或安防护栏。

## 验收标准

- AI 托管内可进入配置页，模型和知识库可切换查看。
- 规则基线和规则包显示本地就绪；未配置项无法伪激活且有清晰原因反馈。
- 配置来源、敏感信息边界和“非向量知识库”语义可见。
- 新任务包含配置来源，既有任务不会被新配置追溯性覆盖。
- 桌面和移动端无布局遮挡，关键移动操作目标至少 44px，控制台无 error/warning。
- AI、安防、地图标注、产值、运营看板、构建与 Python 离线流程不回归。

## 风险与回滚

- 风险：前端示例被误解为真实模型接入；配置入口压缩任务列表；任务来源在重新评估时被覆盖；密钥误入前端。
- 回滚：移除 registry composable、配置组件、AI 配置页签和任务 provenance 字段，恢复原三页签 AI 托管中心。
