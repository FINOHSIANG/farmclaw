# AI 托管首版成果

日期：2026-08-25

## 交付内容

- 可解释托管规则引擎：从遥测、节点拓扑和安防状态生成结构化任务。
- 三种模式：观察、辅助托管、自动托管。
- 任务闭环：建议、待审批、批准、提交/模拟、拒绝、阻断和失败。
- 控制台：信任分、运行范围、任务风险、置信度、证据、建议动作、安全护栏和审计记录。
- 安全控制：默认 Dry Run、中高风险人工审批、托管范围白名单、禁止自动撤防/消警、紧急停止、在途异步阻断和重复提交幂等。
- 地图联动：低风险模拟无人机巡航、摄像头异常聚焦与本地巡检任务。

## 验证证据

- `npm run test:ai`：通过。
- `npm run test:security`：通过，4 个围栏、8 个摄像头、12 个唯一编号。
- `npm run build`：通过；保留既有大 chunk 非阻断提示。
- `python tests/test_flow.py`：离线测试通过，在线联调按既有逻辑可在网关未运行时跳过。
- `git diff --check`：通过，仅有 Windows 换行提示。
- Playwright：1440×900 和 390×900 均可操作；自动模式只运行低风险任务，高风险保持待审批；紧急停止/恢复有效；0 个控制台错误。

## 已知边界

- 当前权威托管状态位于前端内存，刷新后重置；生产化应迁移到后端独立 Manager/Pi Agent skill。
- 当前 Gateway 提交只代表请求已送达，不代表真实设备已执行；界面已明确展示此区别。
- 真实设备闭环上线前仍需补齐身份权限、审批 TTL、策略版本、状态持久化、设备幂等与断线租约。
