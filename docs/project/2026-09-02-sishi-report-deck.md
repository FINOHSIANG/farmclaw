# 四时农业 Agent 汇报稿

用途：面向项目负责人、合作方或试点农场的产品汇报

建议时长：12-15 分钟

核心目标：不把汇报做成功能罗列，而是说明“四时已经有什么、为什么还不够、下一阶段如何成为真正的农业 Agent”。

## 第 1 页：封面

### 屏幕文案

**四时**

面向真实农场作业闭环的农业生产 Agent

感知农场，生成计划，协同执行，验证结果

### 讲述要点

“四时的目标不是再做一套农业数据大屏，而是让农场每天面对的数据、风险和工作，能够被一个可信的 Agent 持续理解和推动。”

### 视觉建议

- 主视觉使用真实农田或温室空间图。
- 叠加一条简洁任务链：风险发现 → 生成计划 → 人工确认 → 现场完成。
- 不在封面使用“中国首个”，避免让汇报从产品价值滑向首称争议。

## 第 2 页：当前基础

### 屏幕文案

**我们已经有一副好眼睛和一套安全护栏**

- 数字孪生地图：农田、水产、温室、设施、农机、安防与风险图层。
- 六大业务专题：生产、安全、AI、产值、运营、预警。
- 农机监测：7 台演示车辆，支持运行状态、任务进度、能源、工时、异常与地图双向定位。
- 对象观测：点击水产塘口、地块或温室后，同屏查看对象预警、处置建议与摄像头识别结果；真实视频未接入时明确显示演示边界。
- AI 托管基础：建议、证据、置信度、审批、Dry Run、紧急停止和审计。

### 讲述要点

“当前版本已经不是概念图。它能够展示农场空间，接收 WebSocket 遥测，形成 AI 任务，并明确区分演示、提交和真实执行。这个安全边界值得保留。”

### 视觉建议

- 左侧放当前生产态势页面截图。
- 右侧放 AI 托管任务卡截图。
- 用“已形成”标签标出地图、状态、审批和护栏。

## 第 3 页：真实成熟度

### 屏幕文案

**当前是高完成度驾驶舱原型，不是完整农业 Agent 产品**

| 已形成 | 部分形成 | 尚未形成 |
| --- | --- | --- |
| 地图与专题展示 | AI 规则建议 | 连续 Agent 会话 |
| 状态语义与演示边界 | 审批和审计 | 农事任务闭环 |
| 桌面/移动响应式 | 风险与预测摘要 | 持久化、权限、追溯 |

### 讲述要点

“当前最大差距不是画面，而是工作是否真正完成。系统能说出建议，但还不能稳定地把建议交给人或设备、收回结果并证明这次建议有效。”

### 视觉建议

- 使用三列成熟度矩阵。
- 不用百分比评分，避免让主观评审看起来像测量结果。

## 第 4 页：从驾驶舱到 Agent

### 屏幕文案

**农业 Agent 必须完成七步闭环**

感知 → 理解 → 规划 → 审批 → 执行 → 验证 → 学习

当前优势集中在“感知、理解、初步规划”；下一阶段重点是“执行、验证、学习”。

### 讲述要点

“聊天框不是 Agent。只有当建议进入任务、任务有负责人、执行有回执、结果能验证，这个系统才真正参与了农业生产。”

### 视觉建议

- 七节点水平流程图。
- 前三步使用当前品牌青色，后三步使用待建设的琥珀色，审批作为两者之间的安全闸门。

## 第 5 页：九个 P0 缺口

### 屏幕文案

**三类关键缺口决定产品能否成立**

1. 产品表达：四时品牌未进入界面，Agent 仍是底部输入框。
2. 生产闭环：缺少对象、任务、告警、现场反馈与追溯。
3. 生产基础：缺少持久化、身份权限、稳定路由和执行回执。

### 讲述要点

可展开为九项：

- 四时品牌和农业 Agent 价值未进入首屏。
- Agent 没有可见会话、计划和结果时间线。
- 没有农场、地块、温室和批次的稳定对象导航。
- 当前田块可能被最新遥测自动改写。
- AI 建议没有进入责任人和工单闭环。
- 预警没有统一确认、分派、升级、关闭和复盘。
- 关键状态保存在前端内存，刷新后重置。
- 没有角色、范围和高风险权限。
- 农事、投入品、采收和认证追溯仍未成为页面。

### 视觉建议

- 三个大组，每组列三项，不使用九张同质卡片。

## 第 6 页：目标用户的一天

### 屏幕文案

**四时每天替农场把问题推到结果**

| 时间 | 用户动作 | 四时动作 |
| --- | --- | --- |
| 07:30 | 查看早报 | 汇总天气、遥测、风险和今日计划 |
| 08:00 | 审批灌溉建议 | 展示依据、参数、影响范围和预期效果 |
| 10:00 | 巡检人员到场 | 下发工单，支持拍照、定位和语音记录 |
| 11:00 | 任务完成 | 对比动作前后指标并请求复核 |
| 17:30 | 交接班 | 汇总完成、失败、未处理和明日风险 |

### 讲述要点

“这个时间线就是产品最重要的验收脚本。每一步都有用户、有对象、有状态、有证据，不再只是一张看板。”

### 视觉建议

- 使用一天的时间轴。
- 用一个真实作业贯穿全页，不并列多个虚构故事。

## 第 7 页：目标信息架构

### 屏幕文案

**任务优先，对象承载上下文**

- 今日：早报、风险、待审批、今日作业。
- 农场：地图、地块、温室、批次、设备。
- 作业：日历、任务、工单、巡检。
- 智能：会话、建议、审批、知识、审计。
- 台账：投入品、采收、质量、成本、追溯、报告。

### 讲述要点

“地图仍然重要，但它从整个系统的唯一容器，变成农场对象的一种空间视图。这样地图服务异常时，用户仍能处理告警和任务。”

### 视觉建议

- 使用五个一级入口的树形结构。
- 系统管理放在右上角账户区，不与日常入口同权重。

## 第 8 页：三个标志性场景

### 屏幕文案

**用三个闭环证明四时不是大屏**

1. 灌溉闭环：墒情异常 → 建议 → 审批 → 派单/设备回执 → 恢复验证。
2. 病虫害闭环：现场照片 → 辅助判断 → 专家复核 → 防治任务 → 复查。
3. 批次追溯闭环：农事与投入品记录 → 采收 → 检测材料 → 二维码报告。

### 讲述要点

“这三个场景分别证明四时能处理实时生产、农业专业判断和可信结果。它们比继续增加看板更能建立产品壁垒。”

### 视觉建议

- 三条短流程并列，每条只保留五个节点。
- 明确哪些节点属于人，哪些属于 Agent，哪些属于设备或数据源。

## 第 9 页：移动端不是缩小的大屏

### 屏幕文案

**桌面负责判断，移动端负责现场完成**

- 桌面：多对象分析、计划、审批、策略和报告。
- 移动：我的任务、紧急告警、扫码、拍照、语音、定位和离线草稿。
- 关键正文至少 12px，触控目标至少 40px。

### 讲述要点

“当前移动端技术上可以使用，但地图、分析面板、专题栏和输入框同时竞争空间。下一版应按现场任务重新设计，不是继续压缩桌面布局。”

### 视觉建议

- 左侧展示当前移动页面。
- 右侧用线框图展示新的‘我的任务’和‘现场反馈’页面。

## 第 10 页：90 天路线

### 屏幕文案

| 阶段 | 目标 | 关键交付 |
| --- | --- | --- |
| 0-30 天 | 让 Agent 被看见 | 四时品牌、今日工作台、Agent 会话、对象选择、地图解耦 |
| 31-60 天 | 让建议变成工作 | 持久化对象、任务工单、告警闭环、权限、执行回执 |
| 61-90 天 | 让结果可信 | 知识引用、多模态、投入品、追溯、移动现场、效果指标 |

### 讲述要点

“第一阶段改主体验，第二阶段补作业闭环，第三阶段补专业知识和可信台账。三阶段都可以单独演示和验收。”

### 视觉建议

- 一条三段路线图。
- 每段只保留一个目标、三个交付和一个验收场景。

## 第 11 页：用结果验收

### 屏幕文案

**成功标准不是页面数量**

- 效率：首屏 10 秒识别最高优先事项，高风险 5 分钟内确认。
- 闭环：AI 建议转任务率、任务按期关闭率、现场记录耗时。
- 可信：建议来源覆盖率、具名审批率、执行回执覆盖率、误报率。
- 价值：节水、节电、节肥、节药、减损、增产和记录完整率。

### 讲述要点

“所有模型指标最后都要回到生产结果。四时不仅要统计建议被点了多少次，还要知道建议有没有完成，完成后有没有改善。”

### 视觉建议

- 使用四行指标，不使用大数字英雄卡。
- 每项指标附数据来源，避免把目标当成现状。

## 第 12 页：需要决策

### 屏幕文案

**今天需要确认三件事**

1. 定位：采用“面向真实农场作业闭环的农业生产 Agent”。
2. 试点：选定一个真实农场和三条闭环验收场景。
3. 边界：首版坚持人工审批和执行回执，不做无回执的自动控制。

### 讲述要点

“如果这三件事确认，下一步就不是继续讨论功能，而是按真实对象、真实人员和真实数据拆任务并开始试点。”

### 视觉建议

- 每项决策只提供“确认/调整”两种状态。
- 页脚列出下一次评审时间和负责人。

## 现场演示建议

### 演示顺序，4 分钟

1. 用 30 秒展示当前地图与六个专题，证明感知底座已经存在。
2. 点击 POND-062，展示溶氧下行预警、建议、摄像头识别结论、置信度和“真实视频流未接入”边界；随后通过网关更新一次识别结果，证明弹窗可实时刷新。
3. 进入运营保障的农机监测，筛选异常植保机并定位地图；展示速度、能源、工时、维护计划和演示遥测标识。
3. 进入 AI 托管，展示证据、风险、审批和 Dry Run 安全边界。
4. 指出当前提交后缺少工单、现场反馈和结果验证。
5. 切到目标流程图，演示未来如何把同一建议推进到任务关闭。

### 演示准备

- 使用固定分辨率和固定浏览器缩放。
- 预先准备在线和离线两套状态截图。
- 明确所有 `demo-baseline` 数据，避免被误解为真实农场数据。
- 准备一个固定的灌溉场景，保证建议、对象、审批和结果前后一致。
- 若网关不可用，直接使用录屏或截图，不在汇报现场排查服务。

## 常见问答

### 这和普通农业大屏有什么不同？

普通大屏主要回答“发生了什么”；四时还要生成计划、推动任务、接收回执、验证效果并形成台账。

### 这和农业问答机器人有什么不同？

问答机器人给知识答案；四时的每条建议都绑定真实农场对象、当前数据、审批权限和执行结果。

### 为什么不直接全自动控制设备？

当前设备协议、身份权限、幂等、断线租约和执行回执尚未完整。先建立可审计的人机协同闭环，比制造“自动化已完成”的错觉更安全。

### 为什么不继续把功能放在地图上？

任务、会话、审批、报告和台账需要稳定 URL、筛选和历史。地图适合空间判断，不适合承载所有业务结构。

### “中国首个”还能不能说？

可以在完成限定词和证据审查后使用细分表述，不建议使用没有范围的宽泛首称。当前优先讲清楚“面向真实农场作业闭环”和“可审计执行型”两个差异点。
