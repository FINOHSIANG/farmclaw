# 四时数字孪生地图视觉升级汇报补充

日期：2026-09-02
范围：`farmclaw-dashboard` 默认 OpenFreeMap + MapLibre 地图路径

## 一、这次升级解决什么问题

原地图已经有农田、水域、温室、建筑、作物、安防和风险数据，但视觉上存在三个影响判断的问题：

1. 地块、水体和建筑接近同一平面，数字孪生的空间关系不够明显。
2. 底图、道路、业务点位和专题颜色同时争夺注意力，切换专题后主次不够稳定。
3. 卫星图更像“换了一张底图”，没有针对业务对象做对比度和色彩处理；选中围栏时也只看到中心点，难以确认实际范围。

## 二、本轮已落地的前端提升

页面品牌入口已由技术底座名更新为“四时 · 数字孪生农场”，浏览器标题、常规工作台和对外大屏保持一致；Farmclaw 继续作为底层网关和代码模块名称，不与产品品牌混用。

### 1. 空间层级

- 农田、鱼塘、水域、绿地增加独立轮廓层，边界不再依赖黑色缝隙辨认。
- 建筑和温室增加落地面、挤出体和 footprint 轮廓，使用垂直渐变和受光方向建立体积感。
- 园区边界增加暗色 casing 与细实线，避免边界在复杂底图上断裂。
- 默认视角调整为更适合观察空间关系的俯视角度：`zoom 15.45 / pitch 52 / bearing -7`。

### 2. 专题聚焦

六个专题拥有独立的图层透明度配置：

- 生产：保留地块与作物细节，突出种植区、水产区和业务标注。
- AI 托管：增加土壤风险热力图，让建议对象和风险区域同时可见。
- 安防：压低农田背景，突出围栏、摄像头、设施和巡航轨迹。
- 产值：压低空间底图，保留预测点的大小、产业颜色和指数分布。
- 运营：压低作物点，突出设施和建筑关系。
- 预警：压低背景，突出离散风险事件，避免多张热力图混色。

### 3. 卫星图业务化

卫星图增加低饱和、受控对比度、亮度范围和线性淡入；开启后同步降低业务面填充强度，使真实影像可读但不盖住边界、点位和风险标记。

### 4. 选中反馈

点位继续使用中心环和状态色；多边形对象额外绘制完整面域的半透明填充与虚线边界。这样点击电子围栏后，用户能同时看到“对象在哪里”和“对象覆盖到哪里”。

### 5. 地图遮罩

网格尺寸从 48px 调整为 56px，边缘压暗减弱，中央地图保持清晰，控制面仍然拥有足够的层次感。

### 6. 响应式地图视口

- 地图初始化、窗口缩放和大屏切换统一使用 MapLibre 的 `setPadding`，业务中心会主动避开桌面两侧面板与移动端底部工作面板。
- 桌面、平板、移动端分别计算可用视野；电子围栏聚焦仅增加 18px 对象呼吸区，不再与全局留白重复计算。
- 地图销毁时同步解绑窗口监听，避免重复进入页面后产生多次尺寸更新。
- 专项校验增加真实 API 调用顺序验证，可发现无效构造参数、重复留白和当前版本不支持的相机选项。

### 7. 第二轮数字孪生精修

- **空间对象有身份**：农田、塘口、水系、绿地、建筑、温室六类面对象统一补充孪生编号、对象类型、状态、数据来源和业务档案关联状态；点击后不再只显示一块“无名多边形”。
- **农业材质可辨识**：种植地块叠加低对比度田垄纹理，塘口叠加水波纹理，在不依赖高饱和色的情况下快速区分耕作面与养殖水面。
- **体量不随缩放失真**：建筑和温室分别采用 13 米、8 米的稳定演示高度，缩放只改变观察距离，不再造成设施“越放大越长高”的错误感知。
- **语义缩放降噪**：作物散点在低缩放级别隐藏，设施、摄像头及常规标签参与碰撞避让；用户先看园区结构，放大后再看作物和设备细节。
- **图层栈重新分工**：地表与纹理位于道路下方，建筑体量、园区边界和电子围栏位于道路之上、底图标注之下，告警、选中反馈和业务标注保持前景可见，避免边界线压住地名与道路信息。
- **选择上下文更准确**：只有选中摄像头或电子围栏时才降低其他安防对象透明度；点击普通建筑不会误触发安防全局降噪。
- **点击不再穿透**：业务点、摄像头或围栏与地块重叠时，优先响应前景对象；摄像头位于围栏面内时明确采用“摄像头优先、围栏其次”的单对象裁决，避免弹窗互相覆盖。
- **复杂面定位更可靠**：凹多边形和 MultiPolygon 使用面内代表点作为弹窗与选中锚点，锚点不会再落到地块范围外。
- **移动端弹窗完整可读**：孪生对象弹窗进入地图中部安全区，并以紧凑双列展示对象字段，避开顶部专题卡片、地图工具与底部工作面板。
- **演示边界透明**：空间对象弹窗明确标注“演示空间对象，不代表真实权属或生产状态”，避免演示底图被误读为确权或生产数据。

### 8. 农机运行监测与地图联动

- **独立资产口径**：新增 7 台演示农机，覆盖拖拉机、收割机、植保机、播种机、巡检车、除草机和运输车；农机作为动态资产单独统计，不并入原有 8 台固定设施。
- **运行信息完整**：看板展示作业状态、当前任务、任务进度、速度、油量或电量、今日与累计工时、作业模式、区域、操作员、最近信号、维护计划和异常说明。
- **地图状态可读**：运营专题增加农机状态光晕、方向图标和遥测新鲜度角标；高缩放标签同步显示运行状态、任务进度及数据新鲜度。
- **双向选择联动**：点击农机卡片会聚焦地图并打开运行孪生弹窗；点击地图农机则自动切换到农机清单、高亮对应车辆并滚动到可见位置。
- **筛选同步**：作业中、待机、充电中、异常、离线五类状态可在面板筛选，地图图层与清单同步收敛，避免统计和空间表达不一致。
- **遥测语义分离**：运行状态与数据新鲜度独立显示。“网关在线”不等同于“农机在线”，静态样例统一标记为“演示遥测”。
- **能力边界明确**：本轮仅提供状态查看、筛选、定位和最近遥测，不提供远程启停、自动调度、轨迹回放或维修工单，避免把演示交互误解为真实控制。
- **地图提供方降级**：OpenFreeMap + MapLibre 路径提供完整农机孪生；高德地图路径暂不伪造定位能力，会给出明确的暂不支持提示。

后续接入真实农机终端时，建议以稳定 `machine_id` 为主键，按 WGS84 上报 `longitude / latitude / heading / speed_kph / status / fuel_percent 或 battery_percent / task_id / task_progress / observed_at / source`。前端可直接更新独立农机 GeoJSON source，不需要重算农田和建筑等静态空间对象。

### 9. 对象级预警与摄像头观测

- **弹窗从身份卡升级为观测卡**：空间对象保留编号、类型、状态、来源和业务档案，同时增加对象预警和摄像头识别结果，不再需要跳出地图才能理解风险。
- **预警可执行**：展示等级、数量、异常标题、判断依据、处置建议和观测时间；POND-062 使用“溶氧下行预警”作为可复现演示样例。
- **摄像头结果可验证**：展示画面槽位、摄像头编号、在线状态、识别结论、置信度和识别指标；只有可信来源、在线、新鲜且实际开始播放的视频才显示 `LIVE`，快照、离线、过期和未绑定状态分别表达。
- **真实与演示严格分开**：没有媒体地址时显示“演示识别 / 真实视频流未接入”；真实流、快照和演示三种模式不会共用 LIVE 标识。
- **无刷新更新**：Farmclaw observer 接收 `twin_observation` / `camera_observation`，按 `twin_id` 以 patch 或 snapshot 方式更新已经打开的地图弹窗，并支持清除旧预警、媒体和识别结果。
- **移动端可读**：对象卡在 390×844 视口内使用内部滚动，顶部地图语境和底部专题/Agent 操作仍保留。

真实接入时建议由服务端将 RTSP/GB28181 转换为浏览器实际支持的流格式，或提供带短期签名的 HTTPS 快照；跨域媒体 origin 需显式加入白名单，不要把摄像头凭据写入前端 GeoJSON、环境变量或日志。

## 三、汇报时建议展示的 90 秒路径

1. **生产态势**：先展示地块轮廓、河道、建筑和温室的空间层级，说明地图从“平面数据”升级为“可判断的数字孪生空间”。
2. **安防巡防**：切换专题，点击一条电子围栏，展示背景降噪和完整面域选中反馈。
3. **运营保障**：进入“农机监测”，先筛选异常车辆，再点击植保机卡片，展示地图定位、状态色、任务进度、能源、工时、维护计划和异常说明；关闭弹窗后直接点击地图农机，展示地图到面板的反向联动。
4. **预警中心**：展示离散风险事件，说明风险点大小与风险分数对应，背景不会抢夺注意力。
5. **产值预测**：展示点位大小和产业颜色，说明预测信息叠加在真实空间上，而不是脱离地块的统计图。
6. **卫星图**：开启卫星图，说明影像、业务边界和专题点位可以同时阅读。

建议在第 1、2 步之间增加一次“地块与前景点位重叠点击”演示：先点击农田查看六项空间对象信息，再点击其上的摄像头或设施，证明前景对象优先、弹窗不互相覆盖。

## 四、验收结论

- 地图专项校验：通过，覆盖桌面、平板、移动端视口计算，六类空间对象、两类农业纹理、稳定建筑高度、图层顺序、图标避让、凹多边形与 MultiPolygon 面内锚点，以及农机状态、新鲜度和选中反馈。
- 农机专项校验：通过，覆盖 7 台农机、唯一 ID、五类状态统计、实时/过期/演示新鲜度、坐标过滤、速度/能源/进度范围、GeoJSON 属性及面板—地图接线。
- 对象观测专项校验：通过，覆盖 POND-062 高风险预警、实时/快照/演示媒体边界、URL 协议过滤、网关字段映射和弹窗接线。
- 生产构建：通过。
- 桌面端 `1440×1000` 与移动端 `390×844`：已完成农机监测渲染、异常筛选、卡片定位、地图反向点选、弹窗和列表高亮复核；异常与离线信息可读，移动端支持展开/收起分析区。
- 本地网关未启动时仍会产生已知 WebSocket 连接失败日志，本轮地图改动未新增应用错误。
- 构建仍保留现有的大包体积提示，后续可把 MapLibre、Three.js 与专题模块继续拆包。

## 五、下一阶段建议

本轮解决的是“看得清、分得开、点得准”。下一阶段应把地图对象与真实农业业务闭环连接起来：

- 建立农场 > 地块 > 温室 > 批次 > 任务的稳定对象 URL。
- 将地图选中对象接入任务、告警、巡检和台账时间线。
- 接入真实遥测后补充数据新鲜度、缺失率和校准状态。
- 对接农机 CAN/北斗终端与真实作业单，补充轨迹抽稀、越界判断、油耗效率和保养预测；远程控制必须单独建设权限、审批、幂等与审计链路。
- 在移动端增加现场定位、拍照回传、扫码和离线任务，不继续压缩桌面大屏布局。
