# ADR-0003 使用可解释规则引擎作为 AI 托管基线

日期：2026-08-25
状态：已接受

## 决策

- 首版 AI 托管使用前端纯函数规则引擎，输入来自现有遥测、节点拓扑和安防状态。
- 使用观察、辅助、自动三种模式；自动模式只允许低风险、可回退任务自动提交。
- 中高风险任务必须人工批准后才能提交，高风险不会被“自动模式”绕过。
- “执行”语义分为网关提交、前端安全状态动作和演示模拟，界面与审计不得声称真实设备已完成动作。
- 模型服务后续可以替换任务生成器，但必须遵守相同的任务契约、护栏和审计状态机。

## 原因

- 当前项目没有生产设备控制 API、权限模型或可靠的模型服务。
- 纯函数规则可测试、可复现、可解释，适合作为后续模型评估基线。
- 状态机和护栏比具体模型更需要先稳定下来。

## 后果

- 首版“AI”体现为决策编排和托管流程，不依赖外部 API Key。
- 真实设备闭环、模型推理、策略签名和生产审计需后续在后端实现。
